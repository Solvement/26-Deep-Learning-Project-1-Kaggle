# Auto-research 工作协议

## 先冻结交付与目标

| 交付 | 验收 | 来源 |
| --- | --- | --- |
| 比赛预测 | `submission.csv`，完整 2,000 个官方 ID/顺序，整数标签 0–9；实际上传与得分单独确认 | Kaggle data/rules |
| 模型与复现产物 | 残差 CNN，从零训练，<= 5,000,000 可训练参数；配置、种子、划分、环境、模型/文件校验和和日志齐全 | Kaggle rules / PDF |
| 代码与 Notebook | 可复现训练/推理，清晰执行记录、曲线、最终准确率和参数量；报告首页链接公开仓库 | PDF 第 2–3 页 |
| 报告 | <= 8 页，包括图/表/引用；成员、方法、架构、对比、结果、局限、引用；每人上传 Brightspace | PDF 第 3 页 |
| 研究记录 | 每项方法有来源/假设/预算/结果/结论；保留失败和未能判断的实验 | 用户要求 |

质量目标：课程要求至少 80% 的基线目标并争取 90% 以上。开发集得分只能支持模型选择；官方隐藏测试成绩仍需真实比赛结果。比赛 11 月 6 日 23:59、报告 11 月 9 日 23:59，时区未注明，暂按纽约时间规划并待确认。

## 硬约束与失败条件

- 仅主办方的允许训练数据；没有外部数据、预训练权重或外部教师检查点。
- 不能训练/手标隐藏评测集，不能把公开榜反复反馈当开发集。
- 模型超参数量、数据/ID/标签不合规、非有限 loss、数据或源码指纹不一致：本次实验无效，先诊断。
- OOM/超时/环境失败不等于方法无效；将其记录为工程失败，提出有理由的下一项配置，不连续重试同一失败任务。
- 短程分数不代表最终上限。保留可能慢收敛的方法，延迟判断；不能只挑某一轮最高分来宣称进步。
- 提交异常/未知网络结果先查询原任务；没有确认失败时不得重复创建 GPU 任务。
- 不自动更改公开可见性、不转向付费资源。用户已授权合适的比赛提交：必须是完整训练的合规候选，通过完整 2,000 行/ID/标签/来源校验、查询实际全队剩余次数并防止重复；默认研究循环每天最多 2 次，且不超过全队每天 5 次。当前没有提交任何预测。

## 数据与比较设计

正式研究固定 `split_seed=42`：40,000 训练、5,000 开发验证、5,000 最终确认。模型/增强的 `seed` 独立，复核不同初始化时仍使用相同数据划分。训练与搜索不计算确认集分数；代码测试检查该分区从未进入训练/开发 DataLoader。

确认集只在开发集选定最终候选后评估一次。`cifar_project.confirm` 通过研究目录的独占凭据文件记录此次使用，重复调用会拒绝。确认结果用于最终审计，不能再拿来连续调参；Wilson 区间仅作描述，不是模型优越性的统计证明。官方隐藏测试是另一层最终评测。

已经完成的首个 45k/5k、5-epoch 工程试跑保留为可行性记录，**不进入新的正式比较组**。正式基线和候选都从零训练。

## 每轮闭环

1. **整理现状**：交付、预算、当前可信基线、失败与未知项。
2. **研究与假设**：阅读原始论文/官方实现；记录能否合规迁移、只改什么、预计收益/额外成本、什么结果会否定或暂不能判断假设。
3. **预注册**：冻结代码快照、数据/划分、epoch 计划、种子、评价与停止规则。第一轮单因素比较。
4. **运行前检查**：参数量、配置合法性、GPU 配额、Notebook 模板/源码快照、并发锁和剩余预算。
5. **按证据分配训练**：先工程验证，再至少跨过 warmup 的短程筛选；有希望的候选才安排更长程及不同初始化。采用多阶段筛选思想，不声称实现完整 ASHA/Hyperband。
6. **收集与校验**：只接收完整数据、完整预算、相同代码/环境/划分的结果。服务器 COMPLETE 但缺少有效产物仍算失败。
7. **判断**：同时查看趋势、最近 3 轮平均开发准确率、波动、训练/验证差距、参数量和耗时。记录保留/延长/推迟/失败的依据。
8. **下一轮**：更新假设与队列，重新检查剩余预算；新代码/计划不能混进旧比较组。

## 当前有界执行器

`python -m cifar_project.research plan` 仅检查和展示计划；`... run --output-dir outputs/research-round1` 执行当前队列。后台方法探索/代码修改不是由该脚本自动生成；agent 根据论文与记录更新研究队列。当前已实现的是 GPU 实验执行、恢复、证据收集和筛选判断。

第一轮正式比较：width 32 基线与 width 48 单因素候选，各运行 10 epoch（包含 warmup 后至少 3 轮）。此前工程试跑保守预留 1,200 秒；最多再启动 **2 个私有 GPU 任务，各最长 1,200 秒，总预留不超过 3,600 秒**。失败任务也占用次数/预算，不因失败自动退款重跑。当前只使用账号报告的 GPU 配额。

筛选阶段以最近 3 轮平均开发准确率降低偶然峰值影响；提升 >= 0.5 个百分点且单轮成本 <= 2.5 倍，仅标为“值得延长并复核”。这是筛选阈值，**不是显著性结论、最终选型或自动长训授权**。不足以判断时保留基线并查看学习曲线。

实验状态与 Notebook 快照存在 `campaign.json`/`frozen-template.ipynb`，判断在 `decision.json`。配置、源码、数据、GPU 或 PyTorch 不同的结果不会直接排名。进程中断可用同一命令恢复已确认的运行任务；处于提交不确定状态时停止并人工核对已有任务，防止重复消耗。

## 不确定项与应对

| 问题 | 影响与行动 |
| --- | --- |
| PDF 截止时间未写时区；报名表/注册期限未知 | 采用有余量的纽约时间计划，等待课程确认，不改写原文 |
| 全量下载接口 404，但单文件与比赛挂载可用 | 训练使用 Kaggle 挂载；本地仅下载小样本做工程验证，不以外部数据替代 |
| GPU 型号/软件可能变化，配额有限 | 记录实际环境，比较前核验；环境改变则另建比较组 |
| 验证集自适应过拟合 | 限制搜索、记录全部尝试，保留一次性确认集；最终比较增加独立初始化 |
| 单次短程结果噪声/慢收敛 | 不用一次最高分做决定；延长预算、看趋势并复核，保留暂不能判断的候选 |
| 集成的参数预算解释不明确 | 第一轮采用单模型；采用集成前向课程确认 |
| 私有仓库与最终公开交付 | 在比赛结束后的报告整理阶段检查内容、授权并按规则公开；当前保持私有 |

下一阶段优先依据真实曲线判断容量/优化/泛化瓶颈，再从文献队列选择方法。报告整理与复现记录随实验同步进行，避免最后才补证据。

用户最新安排：暂缓常驻云服务，优先完成训练与结果比较。云服务草稿已在实例 scratch 中保留，未启用。当前研究状态和结果见 experiment-results.json；重连后的 Kaggle 认证缺失属于实际操作阻塞，不能把历史 RUNNING 当作当前已确认状态。
