# Official development periphery probe

Use the same frozen WRN34-3/300 and ResizeMix WRN22-4/160 checkpoints, plain single-view inference, native BF16 diagnostic context and 5,000 official development images as the translation probe. Both runs must reproduce its clean pixel hash and clean correct count. Retain each central square at its original position, unresized, at widths 30, 28, 26, 24 and 22 pixels. Replace only the removed outer ring with either the fixed RGB normalization mean or the nearest retained edge pixel.

The primary comparison is clean minus masked accuracy at width 28, separately for each replacement. The two-pixel ring removes 240 of 1,024 spatial pixels. Use one percentage point as the practical reference, paired by original image with 10,000 bootstrap draws. A loss of at least one point with a positive lower 95% bound in both replacements supports sensitivity to the removed periphery at this width. If both upper bounds fall below one point, deprioritize a meaningful loss at that width. Different directions or a large mean-only loss leave replacement artifacts as an explanation. Other widths and class slices are descriptive dose-response checks.

Report paired net accuracy change, clean-correct to masked-wrong, clean-wrong to masked-correct, and mean-versus-edge differences. The two checkpoints differ in recipe as well as architecture. Separate model runs do not produce a paired model-versus-model interval. Removing the ring can remove parts of the object or contextual information. Both fills also change the input distribution. This test cannot establish background shortcuts, architecture causality, or behavior on the hidden competition set.

Use a separate authenticated 180-second native guard per model under the canonical lease, campaign deadline and UTC budget. Only aggregate counts, intervals and hashes are persisted. No raw rows, per-image flags, confirmation, hidden images, candidate qualification, policy change or upload.
