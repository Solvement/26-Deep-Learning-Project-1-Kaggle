## Admission scope

V2 proves **local campaign workers inactive**, not that all machine or remote
GPUs are idle. It reads every canonical/archived supervisor under research and
prior report outputs, complete terminal status/aware chronology, native cleanup
proofs where recorded, and all recorded owner/child/watchdog PID+creation-time
identities. Exact hash-bound interrupted attempts explain old raw `training`
receipts; preserved pre-cleanup snapshots remain historical and are associated
with the same reconciled canonical job. A historical failure is not an eternal
busy flag. Unrecognized/nonterminal/unreconciled histories are rejected.

Structured identity fields in the auxiliary automation-state histories are
also checked: old supervisors sometimes overwrote a previous training child
when starting their benchmark. Auxiliary state files preserve **every** duplicate
JSON member rather than taking only the last occurrence; every possible
recorded PID/creation-time pairing is checked. These history records do not
authorize a method, change user resume/pause instructions or override canonical
qualification receipts. Qualification/canonical JSON still rejects duplicates.

Native resource cleanup checks the actual host/spec/ready/completion records;
failed calculations can still have verified cleanup. Legacy records lacking a
native proof are labeled as terminal/recorded-identity checks, never upgraded to
an independently verified native teardown. A missing PID is currently absent;
a different recorded creation time is a reused PID. If an old stamp is missing,
only absence or a current instance created after the recorded job finish proves
the old instance inactive. A protected/unknown matching identity fails closed.
The audit never terminates a process or renames/deletes an unknown lease.

Cloud receipts contribute their local host process identities only. Historical
allocation uncertainty is not relabeled as never allocated, remote inactivity
or a local CUDA subtree. Global NVIDIA observations remain hash/count-only,
unverified and non-authoritative. Live commands identifying managed scripts in
this workspace are rejected even if no completed receipt covers them.

No canonical campaign lease may exist at first admission. After a read-only
audit, v2 atomically creates `results/research/local_lease.json` with its own
CPU-report schema/PID/creation time/nonce. It audits again while owning that
lease and requires unchanged receipt/proof inventory. The authenticated worker
rechecks that same inventory and local process identities before notebook
imports. The lease prevents another managed local GPU job from starting.
Unknown native cleanup retains the matching lease for root reconciliation;
no GPU-training time is charged to the research ledger.

## Evidence and execution

Default preparation is JSON/source work only. The current explicitly pinned d1
adapter reports ten rows/five scored research entries, including TA .867 and
best .878. It does **not** understand the later WRN16-200 or KD experiment.
Future use requires a distinct `scripts/campaign_report_evidence_vN.py`, its
reviewed raw SHA, a matching explicit projection schema, independent tests/CI
and an actual input integration. CLI hashes alone do not establish qualification.
V2 captures the selected adapter's complete statically declared local source
closure. Unknown dependencies reject numerical/runtime/API imports and hidden
dynamic imports throughout their AST. A finite explicit path/raw-SHA list
permits already reviewed mixed-purpose controllers/engines to contain dormant
worker code; that code is hashed, not executed. The metadata modules' actual
top-level import closure still rejects numerical/API imports and dynamic source
execution, including for those pinned modules. Real JSON loading must introduce
no numerical/runtime/API modules. The old adapter cannot be overwritten or
relabeled. This is an audited metadata boundary, not a claim that each complete
controller module contains only pure functions.

Explicit root execution starts a **new v2 worker** under the frozen native
process-tree guard. Its own source/argv/nonce/host/child/bootstrap and actual
Job/session membership are authenticated before numerical/notebook imports.
Only that process and its kernel receive `CUDA_VISIBLE_DEVICES=-1`; the caller's
environment is restored. A kernelspec cannot override that value. The complete
CPU reservation is at most 240 seconds, with time reserved for PDF/rendering,
and never extends beyond 2026-11-05 05:30 UTC. The experiment stop stays 05:00 UTC.

Only the two self-contained new public-snapshot cells execute. Their real fresh
session counts remain 1,2; the original six complete parsed JSON cell objects
(source, outputs, counts 1-6 and metadata) remain exactly equal. Original raw
Notebook SHA and canonical cell-object hashes remain separately labeled. The
public snapshot is embedded and saved beside the Notebook with identical bytes.
No cached output is described as newly executed, and no counts are renumbered.

Reuse only parameterized pure preparation/composition functions from the frozen
wrapper. V2 owns its new cell extensions and complete research renderer: all
measured rows and scored receipts are shown, including future explicitly typed
200-epoch results. An `engineering_preflights` list is rendered separately in
Notebook outputs and report text; alpha-zero hard-control timing is explicitly
not positive-KD speed, accuracy or admission. A new two- or three-page research
PDF is appended to the actual frozen primary PDF; actual total pages cannot
exceed eight (the pinned original has five pages). Every
page is rendered to PNG. Root must review every page, new/old cell and PNG for
layout/privacy before publishing. `publication_ready` remains false regardless
of a successful execution. Private native requests/process inventories remain
ignored; public metadata contains only hashes/counts and audited projection.
