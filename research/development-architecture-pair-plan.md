# Matched terminal WRN architecture diagnostic

Compare WRN34-3 against WRN22-4 using the archived seed-2026 40k/160 runs `wrn34_3_s2026` and `regularized`. Their effective training configurations differ only in depth and width. Source bytes, official split, normalization and recorded training environment match. Use the online model tensor state from each completed epoch-160 `last.pt`, rather than the previously selected checkpoints. Confirm each history, step count and terminal state against its own artifacts. This is a retrospective comparison of two trained instances, not a new randomized multi-seed experiment.

Evaluate the same 5,000 official labeled development images, in the original order, with the existing clean and five synthetic cases and fixed `center80_shift20` inference. Use the explicit stable native BF16 diagnostic context, not the historical cuDNN-autotuned benchmark context. Match every transformed input hash across the two models and the frozen suite. Save only aggregate metrics, counts, intervals and provenance hashes.

Report signed WRN34 minus WRN22 clean, mean stress and individual case differences. Use 10,000 paired original-image draws with the five stress views kept together. For interpretation, a one-percentage-point clean or stress gain with a positive interval and no individual case loss over one point would justify considering a separate prospective study. If the upper interval excludes one point, this comparison weakens that magnitude of improvement on the corresponding metric. A wide interval remains inconclusive. Mixed case effects remain visible even when the mean improves.

Depth and width change jointly, and parameter counts are close but unequal. Reused development images and one training seed limit inference. Historical wall times can be reported as descriptive and do not establish a controlled speed effect. Historic public results used different selected epochs and inference policies. This diagnostic does not change the leaderboard reference, promotion criteria, model selection or delivery. No confirmation or hidden input is accessed.
